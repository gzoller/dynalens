Semantics (how it plugs into your current model)

1) New path shapes

You already support [] and []?. Add map-flavored wildcards:
	•	m.values[] → iterate values
	•	this = the value
	•	loop symbol: values not added; we keep m as the map symbol; expose the current key via a function key() if needed (see below)
	•	m.keys[] → iterate keys
	•	this = the key
	•	m{} → iterate entries (pairs)
	•	this = the entry receiver exposing two pseudo-fields: key, value
	•	Option forms: m?{}, m?.values[], m?.keys[]
Your suffix order stays consistent: any [] comes before ?.
So:
	•	m?{}  (optional entries)
	•	m.values[]? (optional values) — but I’d recommend the clearer m?.values[]

Parser tweak (minimal): extend your parseSeg to recognize {} as the entries wildcard suffix (like you do with []).
Rewrite/validation (CorrectPath.rewritePath) mirrors what you already do:
	•	on a bare m in loop scope: if the user uses m in a value context (no wildcard), keep as-is; in a map LHS choose the flavor they wrote (values[], keys[], or {}). No implicit conversion to {} — be explicit.

2) Receiver & scope inside loops
	•	m.values[]:
	•	this = value
	•	Add helper key() (a zero-arg method) to retrieve the current key from the loop frame when you’re iterating values.
	•	Keep m bound (like your items loop symbol); also expose m[] (the whole value collection) analogously to lists.
	•	m.keys[]:
	•	this = key
	•	m{}:
	•	this.key, this.value as pseudo-fields (like a tiny receiver with two fields)
	•	You may also bind loop symbol m{} in ctx (mirroring your items[] exposure) to allow RHS to reference the whole entry stream if needed.

3) RHS contract for => (map)
	•	m.values[] => expr: expr returns a new value; keys preserved.
	•	m.keys[] => expr: expr returns a new key; value preserved; you must check for duplicate keys and either:
	•	fail with a clear DynaLensError("duplicate key after rekey: ..."), or
	•	keep first/last (define policy; I recommend fail to be safe).
	•	m{} => expr:
	•	If expr returns entry(k, v), rekey to k and set value to v.
	•	If expr returns a non-entry scalar, treat it as a new value (key unchanged).
	•	If expr returns None, drop the entry (like filtering).
	•	If expr returns Some(...), unwrap and apply the same rules (lets you conditionally rekey/value-change with Option).

This keeps the mental model identical to lists: the LHS determines iterator and what this is; the RHS decides what you yield.

4) Collection methods on maps

You’ve reworked methods to run when this is a collection. Map collections get analogous methods:
	•	On m.values[] and m.keys[]: all the list methods you already have (e.g., limit, reverse, clean, distinct, sortAsc(field) — where field refers to receiver of value if it’s a case class, otherwise natural order)
	•	On m{} (entries): methods operate on the entry stream.
	•	filter(...) uses key, value in predicate
	•	distinct(...) by key or value (explicit)
	•	sortAsc(key) or sortAsc(value.<field>) etc.
	•	These map-flavored methods should return a Map (not a list), since the input is a map iterator. (Your runtime can realize this by knowing it’s in the {} mode and folding entries back into a LinkedHashMap to preserve order if needed.)

5) Data-access helpers
	•	m.get(k) → Option[V] (cleaner than introducing string subscripts in your path grammar)
	•	m.containsKey(k) → Boolean
	•	m.containsValue(v) → Boolean

6) Type / shape checking (compile-time side)

Extend your SymbolType inference:
	•	Map, OptionalMap already exist in your enum
	•	m.values[] is List-like with element-shape of the value type
	•	m.keys[] is List-like with element-shape of the key type
	•	m{} behaves like List-like of Entry (receiver with fields key, value)
	•	For the purposes of shape checking, the RHS of m{}:
	•	may return a scalar (value rewrite),
	•	or an Entry (k,v),
	•	or Option[…] of either (to support drop/keep via None)
	•	Option-map checks: m?{} / m?.values[] / m?.keys[] should use your existing checkRhsShapeForOptionMap with the inner shape (entry/value/key respectively).

// get(key, default) — default is an *expression*, evaluated only when needed
case class GetFn2(recv: Fn[Any], key: Fn[Any], default: Fn[Any]) extends Fn[Any] {
  def resolve(ctx: DynaContext): ZIO[_BiMapRegistry, DynaLensError, Any] =
    for {
      base <- recv.resolve(ctx)
      k    <- key.resolve(ctx)
      out  <- base match {
        case None =>
          // Option[Map] empty → fallback
          default.resolve(ctx)

        case Some(m: Map[?, ?]) =>
          val mm = m.asInstanceOf[Map[Any, Any]]
          mm.get(k) match {
            case Some(v) => ZIO.succeed(v)
            case None    => default.resolve(ctx) // lazy: only now
          }

        case m: Map[?, ?] =>
          val mm = m.asInstanceOf[Map[Any, Any]]
          mm.get(k) match {
            case Some(v) => ZIO.succeed(v)
            case None    => default.resolve(ctx) // lazy: only now
          }

        case other =>
          ZIO.fail(DynaLensError(s"get() requires Map or Option[Map], found ${other.getClass.getSimpleName}"))
      }
    } yield out
}

M_GET -> { (recv, args, off) =>
  for {
    _ <- checkArgs(M_GET, args, 2, off)                 // (key, default)
  } yield GetFn2(recv, args(0), args(1))
},

case object GetMethod extends CollectionMethodParser {
  val name = M_GET
  def parseFn[$: P](inner: Fn[Any])(using ExprContext): P[ParseFnResult] =
    P(Index ~ "(" ~/ WS0 ~ valueExpr ~ WS0 ~ "," ~ WS0 ~ valueExpr ~ WS0 ~ ")").map {
      case (_, Left(e), _)         => Left(e)
      case (_, _, Left(e))         => Left(e)

    }
